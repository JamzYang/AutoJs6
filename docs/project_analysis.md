**日期**: 2026-01-23

## 1. 项目背景与用户意图

### 1.1 项目背景
用户使用一款名为“风清扬”的硬件设备，该设备支持通过手机控制（点击、滑动等操作），常用于游戏辅助或自动化脚本。该设备宣称支持两种连接模式：
1.  **蓝牙模式 (Bluetooth Mode)**：通过蓝牙无线连接。
2.  **OTG 直连模式 (OTG Serial Mode)**：通过 OTG 线物理连接手机，实现无延迟控制。

### 1.2 用户痛点与意图
*   **痛点**：官方 APP 使用繁琐，且可能存在功能限制。部分用户场景需要通过 **Auto.js** 等自动化脚本工具直接控制硬件。
*   **困惑**：用户在反编译的 Java 源码中只发现了蓝牙相关的代码 (`HID.java`)，但官方确实支持 OTG 直连。用户无法理解为何找不到 USB 通信代码，怀疑自己的分析方向有误。
*   **目标**：
    1.  **理清原理**：弄清楚 APP 是如何实现 OTG USB 通信的。
    2.  **独立驱动**：无需依赖官方 APP，使用 Auto.js 直接编写驱动脚本，实现对硬件的完全控制（不仅是蓝牙，更希望是 OTG 模式）。

## 2. 核心分析发现

通过对代码的深度审查（包括 `fqy-plugin` 和主 APP 源码），我们得出了以下关键结论：

### 2.1 “双模”架构的真相
APP 的架构采用了 **Java + Native (C++)** 混合模式，分别处理不同的通信方式。这是一层巧妙的“伪装”。

*   **蓝牙层 (Java)**：
    *   **位置**：`plugins/fqy-pulgin/.../HID.java` 和 `BleHID.java`。
    *   **实现**：使用标准的 Android `BluetoothGatt` API。代码清晰可见，负责蓝牙设备的扫描、连接和数据发送。
    *   **现状**：用户之前主要关注于此，因此误认为代码不完整。

*   **OTG USB 层 (Native/C++)**：
    *   **位置**：`libfqy.so` (或类似名称的动态库)，通过 `com.main.app.Native` 类调用。
    *   **实现**：
        *   `Native.java` 中声明了 `registerService`、`sendEvent` 等本地方法。
        *   APP 在 `BootBroadCastReceiver` 中监听 `USB_DEVICE_ATTACHED` 广播。
        *   当 USB 插入时，APP 启动 `MainService`，进而调用 Native 方法直接操作 USB 设备文件描述符（File Descriptor）。**这部分逻辑完全封装在编译好的 SO 库中，因此在 Java 源码中找不到 `UsbManager` 的常规调用。**
    *   **证据**：
        *   `AndroidManifest.xml` 中注册了 VID `17224` 的 USB 设备监听。
        *   `Native.java` 存在大量底层硬件交互接口。

### 2.2 通信协议：通过“字符串”统一
这是本次分析**最有价值**的发现。尽管传输介质不同（蓝牙 vs USB），但上层协议是统一的纯文本字符串协议。

硬件设备本质上是一个 **串行通信设备**（Serial Device），它接收特定的文本指令并执行动作。

**指令集示例**：
*   **按下**: `$#md:x,y|` (Mouse Down)
*   **移动**: `$#mm:x,y|` (Mouse Move)
*   **抬起**: `$#mu:x,y|` (Mouse Up)
*   **初始化**: `$#init:`
*   **按键**: `$#kp:keycode|`

**结论**：只要我们能建立通信通道（无论是蓝牙 Socket 还是 USB 串口），**发送完全相同的这些字符串**，硬件就能动！官方驱动的复杂性在于“如何建立连接”，而不在于“协议本身”。

## 3. 技术实现路径 (Auto.js)

基于以上发现，我们确立了使用 Auto.js 独立驱动硬件的技术路线。

### 方案 A：OTG 直连 (推荐，稳定)
由于官方 Native 驱动难以直接调用且被混淆，我们选择**绕过它**，直接使用通用的 USB Serial 协议。

1.  **原理**：大多数此类硬件使用标准 USB 转串口芯片（如 CH340, CP2102, FT232）。
2.  **实现**：
    *   使用 Auto.js 加载一个轻量级的 USB Serial Java 库（或直接用 Android API 实现简易串口通信）。
    *   识别 VID `17224` (0x4348)。
    *   建立连接后，直接写入上述协议字符串。
3.  **优势**：无需 Root，延迟最低，无需官方 APP 后台。

### 方案 B：蓝牙直连 (备份)
如果 OTG 方案遇到硬件兼容性问题（如缺少 OTG 线），依然可以使用蓝牙。

1.  **原理**：直接复刻 `HID.java` 的逻辑。
2.  **实现**：
    *   Auto.js 调用 Android Bluetooth API。
    *   连接 GATT 服务 (UUID: `4fafc201...`)。
    *   写入特征值 (UUID: `beb5483e...`)。
3.  **优势**：无线便携。
